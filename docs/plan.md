# Okno OS на базе ReactOS — план (утверждён 29.10.2026)

## 1. Что такое ReactOS сейчас (проверено 29.10.2026)

**Исходники открыты:** GPL-2.0-or-later, часть кода под LGPL/BSD. Форк законен, условие одно: наш код тоже
открыт под GPL. Около 10 млн строк: ядро NT и драйверы свои, пользовательские DLL во многом взяты из Wine.

**Состояние:** версия 0.4.16 от 29.08.2026, статус «альфа», проекту 28 лет. Официальный выпуск только 32-битный (x86),
программам он сообщает уровень Windows Server 2003 (NT 5.2). 64-битная версия есть только в ночных отладочных сборках.

**Запустил в виртуальной машине** (снимки — [kb/reactos-0.4.16-test.png](kb/reactos-0.4.16-test.png)):

| Сборка | Что проверял | Итог |
|---|---|---|
| 0.4.16 x86 | рабочий стол, Проводник, командная строка | работают; все процессы вместе занимают ~50 МБ памяти |
| 0.4.16 x86 | PuTTY, 7-Zip 25.01 (установка и запуск) | работают |
| 0.4.16 x86 | Python 3.13, Firefox 115 ESR, свежий Firefox | не запускаются: им нужны Windows 7 / 8.1 / 10 |
| ночная x64 | загрузка на стандартном контроллере IDE | синий экран, STOP 0x1E в pciidex.sys |
| ночная x64 | загрузка на SATA (AHCI) | грузится до рабочего стола |
| ночная x64 | 32-битная PuTTY | не запускается совсем: слоя WoW64 нет |
| ночная x64 | 64-битная PuTTY | работает |

**По исходникам:**

- USB 3 (xHCI) — заготовка на ~600 строк, в ней 29 мест «не реализовано». На ПК после 2015 года все порты USB — это xHCI.
- NVMe — драйвера нет, а почти все современные SSD — NVMe.
- Wi-Fi — драйверов нет. Сетевой стек NDIS 5.1, а драйверы Wi-Fi от Windows 7 и новее — NDIS 6.
- Видео — только модель драйверов времён XP, WDDM нет. Драйверов XP для видеокарт новее ~2015 года не выпускали,
  так что на современной видеокарте нет ускорения.
- Многоядерность — только отдельный экспериментальный пункт в меню загрузки.
- Загрузчик UEFI экспериментальный и не подписан Microsoft, поэтому Secure Boot придётся отключать.

**Вывод:** на современном ПК (NVMe, USB 3, Wi-Fi, видеокарта после 2016 года) ReactOS сегодня не видит диск и не ставится,
современные программы на ней не запускаются.

Сильная сторона ReactOS — это ядро NT: программы и драйверы Windows она запускает напрямую, без прослойки.
Отсюда путь: довести её до уровня Windows 10 в двух местах:
- функции, которые вызывают программы (API);
- модели драйверов StorPort, NDIS 6 и WDDM — чтобы ставились официальные драйверы производителей для Windows 10.

## 2. Метод: совместимость — это измеримая очередь задач

- **Стенд.** CI на каждый пуш собирает образы x86 и x64. Затем в QEMU с KVM (на раннерах GitHub он есть) прогоняет
  набор программ и выдаёт таблицу «запустилась / нет» со снимками. Сегодня вручную: 3 из 6.
- **Анализатор импортов.** Для топ-500 программ из каталога winget разбираем импорты PE-файлов и сверяем их
  с экспортами наших DLL. Получаем список недостающих функций, отсортированный по числу программ, которым они нужны.
  Работа идёт сверху этого списка.
- **Только документированное и открытое:**
  - WDK документирует интерфейсы драйверов: StorPort, NDIS 6, WDDM DDI.
  - Microsoft открыла KMDF под MIT, ReactOS уже взяла его в 0.4.16.
  - Готовые открытые реализации: Wine (WoW64 и DLL уровня Windows 10, LGPL), xHCI из Haiku (MIT),
    драйвер NVMe OpenFabrics (BSD), wpa_supplicant (BSD) для WPA2/WPA3.
- **Связь с ReactOS.** Их изменения регулярно вливаем к себе. Свои изменения держим отдельными модулями,
  чтобы слияния не превращались в ад.

## 3. Этапы

**Этап 0 — стенд, ~1 месяц.**
- Форк, CI x86/x64, автотест программ в QEMU, анализатор импортов, первый замер на топ-100 программ.
- Меряем скорость: сколько программ в неделю удаётся довести до запуска. По этой цифре пересчитываем сроки этапов 1–5.

**Этап 1 — современные программы (на x86, там быстрее отлаживать).**
- Недостающие функции уровня Windows 7 → 8.1 → 10 по очереди из анализатора.
- Браузер: первым проверяем Supermium (Chromium с поддержкой XP) как быстрый вариант, затем актуальные Chromium/Firefox.
- Python, Telegram, 1С, КриптоПро, офисный пакет.
- Готово, когда из топ-100 запускается не меньше N программ. N назначаем после замера на этапе 0.

**Этап 2 — 64 бита по умолчанию.**
- Стабильная x64, без синего экрана на IDE.
- WoW64, чтобы 32-битные программы работали в 64-битной системе (основа — реализация из Wine).
- Многоядерность включена по умолчанию.

**Этап 3 — современный ПК.**
- UEFI и экран через GOP в родном разрешении.
- NVMe, USB 3, сетевые карты Realtek и Intel, HD Audio.
- Готово, когда система ставится и работает на трёх реальных ПК 2016–2024 годов.
- **Первый выпуск Okno:** настольный ПК с проводной сетью, без 3D-ускорения, современные программы работают.

**Этап 4 — ноутбуки.**
- NDIS 6, чтобы ставились официальные драйверы Wi-Fi для Windows 10 (Intel, Realtek, MediaTek); WPA2 и WPA3.
- Батарея, сон, яркость, тачпады (I2C HID).

**Этап 5 — видеокарты.**
- WDDM, чтобы ставились официальные драйверы Intel, AMD и NVIDIA: ускорение, DirectX 11/12, игры.
- До этого экран идёт через UEFI без ускорения, 3D считается процессором. Это самый большой и рискованный кусок.

**Продукт — параллельно с этапами 1–3, только функции.**
- Okno Setup.exe: установка из Windows рядом с ней, без флешки, с переносом файлов, Wi-Fi и браузеров.
- Центр программ: в ReactOS есть RAPPS, добавляем каталог winget.
- Своя система обновлений, русский язык по умолчанию.

**Этап 6 — внешний вид (последним, решение владельца).** Оформление Windows 10 (ReactOS поддерживает темы
`.msstyles`), Пуск, Проводник, экран установки. До этого этапа внешний вид не трогаем.

**Сроки — грубая оценка, после этапа 0 пересчитываем по замеру:**
- этап 0 — 1 месяц;
- этапы 1–3 — 9–15 месяцев до первого выпуска;
- этап 4 — ещё 6–12 месяцев;
- этап 5 — годы.

Для сравнения: команда ReactOS шла до нынешнего уровня 28 лет. Наше ускорение держится на разработке с ИИ.
Это допущение, а не факт, и этап 0 его проверяет.

## 3a. Ближайшая цель — рабочая 64-битная система (решение владельца, 30.10.2026)

Всё упрощаем до одной цели: **64-битная Okno, которая ставится, загружается, использует все ядра процессора
и на которой ставятся и работают базовые 64-битные программы.** Пока она не готова полностью, ничего другого
не делаем.

- **Входит:** сборка x64 (компилятор GCC/RosBE, как у ReactOS; clang — позже), установка, многоядерность,
  функции Windows уровня 7 для 64-битных программ, установка программ: родные 64-битные установщики, MSI,
  zip и **распаковщик 32-битных установщиков** (NSIS, Inno Setup, WiX Burn внутри несут 64-битные файлы/MSI).
- **Потом, после готовой 64-битной системы:** WoW64 (32-битные программы), планы электропитания,
  производительность, драйверы видеокарт и 3D, внешний вид.
- **Оценка:** 1,5–2,5 месяца: x64-сборка с установкой — 1–2 недели, многоядерность — 2–4 недели,
  программы — 2–4 недели (частично параллельно). Железо в оценке — QEMU и ПК с SATA/AHCI; NVMe и USB 3 — отдельная задача.

## 4. Риски

- **«Чистая комната».** ReactOS требует от разработчиков клятвы, что они не видели исходников Windows.
  ИИ учился на интернете, где лежат утёкшие исходники Windows. Поэтому ReactOS наш код, скорее всего, не примет,
  а формально он остаётся под вопросом.
  Меры: ничего из утечек, пишем только по документации WDK/MSDN и по тестам поведения, к ReactOS ничего не отправляем.
  Microsoft за 28 лет ReactOS не судила, но риск остаётся.
- **Secure Boot.** Загрузчик не подписан Microsoft, поэтому Secure Boot нужно отключать. Okno Setup.exe сам:
  - приостанавливает BitLocker (иначе Windows потребует ключ восстановления);
  - перезагружает прямо в настройки UEFI (`shutdown /r /fw`) и показывает, что выключить.
- **Отладка ядра на реальном железе.** Отладчик ядра ReactOS работает через COM-порт. Нужен ПК с COM-портом
  или с разъёмом под планку COM.
- **Скорость разработки** — главная неизвестная, её меряет этап 0.
- **Не заработает и после этапа 5:** игры с античитом в ядре и защищённое видео (DRM). Они проверяют подлинность Windows.

## 5. Решения владельца

1. Форк ReactOS в `Fstrok/okno-os`, код открыт под GPL. Linux не используем.
2. Порядок: программы → 64 бита → настольный ПК → ноутбуки → видеокарты; функции продукта — параллельно;
   внешний вид — последним этапом.
3. Из ReactOS берём только то, что годно в 2026 году и лучше всех доступных вариантов; остальное заменяем
   (решения по каждой части — `kb/decisions.md`).
4. Первый выпуск — настольный ПК с проводной сетью, без 3D.
5. К этапу 3 нужны 2–3 реальных ПК разных лет, хотя бы один с COM-портом.
